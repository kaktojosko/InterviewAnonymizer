# Interview Anonymizer 🎭

**Текущая версия: v4.3.1 Stable.**

Interview Anonymizer — это высокопроизводительный полностью локальный сервис для автоматической анонимизации видео-интервью и создания текстовой расшифровки с разделением по ролям говорящих. Инструмент скрывает лица (сверхбыстрый детектор YuNet), изменяет голос (Pitch Shifting) и формирует отдельный `.txt`-транскрипт диалога (`Спикер 1`, `Спикер 2`, ...), обеспечивая **100% приватность без облачных API**.

Специально оптимизирован для работы с длинными видео (часовые мультиязычные интервью Ru/En и др.) на обычных процессорах (CPU) без тяжёлого PyTorch-рантайма, а также поддерживает **опциональное ускорение транскрибации на видеокартах NVIDIA (CUDA)**.

## ✨ Ключевые особенности

* **Локальная автотранскрибация по ролям (v4.0+)**: Автоматически создаёт отдельный UTF-8 `.txt`-файл с таймкодами и репликами каждого участника (`[ЧЧ:ММ:СС - ЧЧ:ММ:СС] Спикер N: ...`). Включена по умолчанию и отключается в один клик в UI (или флагом `--no-transcribe` в CLI).
* **Ускоренный CPU-конвейер (v4.3)**: Нативная планарная обработка видео в `YUV420p` без полнокадровых конвертаций `YUV↔BGR` (вдвое меньше трафика и RAM в пайпах FFmpeg), фоновое кодирование питч-аудио в `AAC` с однопроходной stream-copy сборкой `.mp4`, векторизованная фильтрация гудков и плотная упаковка окон `Whisper INT8` с параллельными воркерами `CTranslate2` и адаптивным пропуском DTW-выравнивания на монологах.
* **Опциональный режим GPU (NVIDIA CUDA, вкл. RTX 50-серию Blackwell)**: По умолчанию сервис работает на `CPU`, а при подключении видеокарты в настройках UI (или флагом `--device cuda`) переносит распознавание `Whisper` на GPU (`float16` Tensor Cores) и выполняет его **параллельно** с блюром лиц на CPU без конкуренции за процессорные ядра.
* **Мгновенная остановка задачи («Прервать»)**: Кнопка отмены в веб-интерфейсе останавливает загрузку файла, параллельные воркеры размытия лиц, дочерние процессы `FFmpeg`, распознавание на GPU/CPU и диаризацию с автоматической очисткой всех временных файлов.
* **Мультиязычность и Code-Switching (Ru + En и ещё 97 языков)**: Поддерживает интервью, где собеседники переходят с русского на английский (IT-термины, англицизмы) или говорят на разных языках внутри одной записи.
* **Точная диаризация на оригинальном тембре**: Аудио для распознавания и разделения голосов извлекается параллельно *до* питч-шифтинга во временную директорию задачи и гарантированно удаляется после завершения, сохраняя эталонную точность голосовых эмбеддингов.
* **Экстремально быстрый ML для видео**: Используется легковесная нейросеть **YuNet (OpenCV)** (всего 1.7 МБ). Детекция происходит на сжатой до 480p копии кадра, что даёт кратный прирост скорости.
* **Математическая интерполяция**: Нейросеть сканирует лишь каждый 28-й кадр. Позиции блюра в промежуточных кадрах плавно и точно высчитываются математически. Встроена защита от «перепрыгивания» блюра между лицами.
* **Zero-Copy Архитектура**: Видео читается напрямую через `ffmpeg readinto` в планарный `YUV420p` с кольцевым буфером, что полностью исключает лишние аллокации памяти и конвертации цвета в горячем цикле.
* **Умная работа с потоками**: Прямая нарезка видео на чанки (без демуксинга), параллельное искажение голоса в фоне и интеллектуальная балансировка CPU/GPU без перегрузки RAM.
* **Выбор количества обработчиков**: В интерфейсе можно выбрать количество воркеров для конкретного запуска: `1`, `2`, `4`, `6`, `12`, `16` или своё значение.
* **Анонимизация голоса**: Быстрое искажение тембра (pitch shifting) с помощью нативных аудио-фильтров FFmpeg (`asetrate`, `atempo`) без полной загрузки в оперативную память.
* **Высококонтрастный Claymorphism UI**: Современный веб-интерфейс с кастомными выпадающими списками, поддержкой Светлой и Тёмной темы (`localStorage`), выбором CPU/GPU, живым логом, мгновенной отменой и раздельным скачиванием `.mp4` и `.txt`.

## 🧠 Локальные модели транскрибации и диаризации

Все модели работают **100% локально** через легковесные движки `CTranslate2` (`faster-whisper`) и `ONNX Runtime` (`sherpa-onnx`). В интерфейсе и CLI доступны 3 профиля распознавания речи:

| Профиль (`id`) | Модель | Движок | Ускорение | Языки | Диск | Пик RAM / VRAM | Назначение |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **`turbo`** *(по умолч.)* | `Whisper Large v3 Turbo` | `faster-whisper` | `CPU` / `GPU CUDA` | **99 языков** (отличный Ru+En code-switching) | ~810 МБ | ~1.5 ГБ | Максимальная точность на смешанной речи, акцентах и редких языках |
| **`parakeet`** | `NVIDIA Parakeet TDT 0.6B v3` | `sherpa-onnx` | `CPU` (`INT8`) | **25 языков Европы** (вкл. Ru, En, De, Fr, Es, Uk) | ~600 МБ | ~1.1 ГБ | Сверхбыстрая пакетная обработка длинных интервью на обычном CPU |
| **`small`** | `Whisper Small` | `faster-whisper` | `CPU` / `GPU CUDA` | **99 языков** | ~245 МБ | ~0.6 ГБ | Ультра-лёгкий режим для ноутбуков и мини-ПК с малым объёмом ОЗУ |

Для разделения по ролям используется двухэтапный алгоритм **Anchor-Centroid Diarization**:
* **Сегментация речи и фильтр гудков**: `pyannote-segmentation-3.0` (`INT8 ONNX`, ~6 МБ) + спектральный фильтр узкополосных гудков ожидания вызова (`Zoom` / `Teams` / `Телемост`).
* **Голосовые эмбеддинги (Voiceprints)**: `3D-Speaker CAM++` (`ONNX`, ~28 МБ) + взвешенная центроидная кластеризация по опорным репликам с привязкой коротких междометий (`«угу»`, `«да»`, `«спасибо»`) к эталонным голосам спикеров.

### Пример выходного файла транскрипта (`.txt`)

```text

[00:00:10 - 00:00:24] Спикер 2: Привет, давай начнём с архитектуры. Мы перенесли основной pipeline на локальные воркеры...
```


## 🛠 Технологический стек

* **Backend**: Python 3.10+, FastAPI, Uvicorn
* **Computer Vision**: OpenCV (`cv2`), YuNet (ONNX)
* **Speech Recognition & Diarization**: `faster-whisper` (CTranslate2 INT8 / CUDA FP16), `sherpa-onnx` (ONNX Runtime), `huggingface-hub`
* **Video/Audio Manipulation**: FFmpeg, `ffmpeg-python`
* **Frontend**: HTML5, Vanilla JavaScript, CSS3 (CSS Variables, Claymorphism)
* **DevOps**: Docker, Docker Compose (CPU по умолчанию + опциональный GPU-оверлей)

## 🚀 Установка и запуск (через Docker)

Проект полностью контейнеризирован. Вам не нужно устанавливать Python или FFmpeg локально, достаточно установленного [Docker](https://www.docker.com/) и [Docker Compose](https://docs.docker.com/compose/).

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/kaktojosko/InterviewAnonymizer.git
   cd InterviewAnonymizer
   ```

2. Соберите и запустите контейнер в стандартном режиме (CPU):
   ```bash
   docker compose up --build -d
   ```

3. *(Опционально)* Если на хосте установлена видеокарта NVIDIA и [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html) (или Docker Desktop с WSL2 GPU на Windows), запустите с GPU-оверлеем, чтобы разблокировать выбор `GPU (NVIDIA CUDA)` в веб-интерфейсе:
   ```bash
   docker compose -f docker-compose.yml -f docker-compose.gpu.yml up --build -d
   ```

4. Откройте интерфейс в браузере:
   ```text
   http://localhost:8000
   ```

> **Примечание о моделях**: При первом запуске задачи с включённой транскрибацией выбранная модель автоматически скачается в примонтированную папку `./models` и в дальнейшем будет загружаться мгновенно с диска без доступа в интернет.

### Полностью автономная (Air-Gapped) сборка образа

Если контейнер планируется запускать в закрытом контуре без доступа к сети, запеките нужные модели прямо в Docker-образ на этапе сборки (`turbo`, `parakeet`, `small` или `all`):

```bash
docker build --build-arg PRELOAD_MODELS=turbo,small -t interview-anonymizer:offline .
```

Модели сохраняются внутри образа в `/opt/preloaded_models`, поэтому монтирование пустой папки `./models:/app/models` не затирает предзагруженные веса.

## 💻 Использование из командной строки (CLI)

Помимо веб-интерфейса, сервис можно запускать напрямую через `main.py`:

```bash
# Стандартный запуск на CPU (анонимизация видео + автотранскрибация моделью turbo)
python main.py -i interview.mp4 -o output/interview_anon.mp4

# Запуск с ускорением транскрибации на видеокарте NVIDIA CUDA
python main.py -i interview.mp4 -o output/interview_anon.mp4 --device cuda

# Быстрая CPU-модель Parakeet, явное число спикеров = 2 и кастомный путь к .txt
python main.py -i interview.mp4 -o output/interview_anon.mp4 -t output/dialog.txt --asr-model parakeet --speakers 2 -w 6

# Только анонимизация видео и голоса (без транскрибации)
python main.py -i interview.mp4 -o output/interview_anon.mp4 --no-transcribe
```

Предзагрузка локальных моделей вручную в `./models`:

```bash
python -m src.model_manager --preload turbo
```

## ⚠️ Хранение файлов и освобождение места

Приложение работает локально и хранит рабочие файлы на вашем компьютере:

* `uploads/` — загруженные исходные видео. Удаляются автоматически после завершения задачи, но могут остаться после аварийной остановки.
* `output/` — готовые анонимизированные видео (`*_anonymized.mp4`) и файлы расшифровки (`*_transcript.txt`). Остаются на диске, чтобы их можно было скачать повторно.
* `tmp/` — временные чанки видео и временные WAV-дорожки (в Docker хранятся внутри быстрой нативной ФС контейнера без замедления через Windows/WSL2 mount). Автоматически очищается при старте и в блоке `finally` после каждой задачи.
* `models/` — локальный кэш скачанных нейросетевых моделей распознавания речи и диаризации (~280–850 МБ в зависимости от выбранного профиля). **Не очищайте эту папку**, если не хотите скачивать модели заново.

Длинные видео могут быстро занимать десятки гигабайт. Периодически проверяйте размер папок `uploads/`, `output/` и `tmp/`, особенно после тестовых прогонов.

### Очистка рабочих файлов (с сохранением кэша моделей)

Перед удалением убедитесь, что нужные готовые видео и `.txt`-транскрипты уже скачаны: очистка `output/` удалит результаты обработки.

PowerShell:

```powershell
docker compose down
Remove-Item -Recurse -Force .\uploads\* -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force .\output\* -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force .\tmp\* -ErrorAction SilentlyContinue
docker compose up -d
```

Bash:

```bash
docker compose down
rm -rf uploads/* output/* tmp/*
docker compose up -d
```

## 🧹 Очистка Docker-кэша

Docker хранит build cache, старые слои образов и остановленные контейнеры. После частых пересборок или больших видео кэш может занимать много места. Текущий `Dockerfile` копирует в образ только код приложения, а `.dockerignore` исключает `uploads/`, `output/`, `tmp/` и `models/`, но build cache Docker всё равно нужно иногда чистить.

Посмотреть, сколько места занимает Docker:

```bash
docker system df
```

Безопасная очистка build cache:

```bash
docker builder prune
```

Более агрессивная очистка build cache:

```bash
docker builder prune --all --force
```

Если сборка падает с ошибкой вида `parent snapshot ... does not exist` или `failed to prepare extraction snapshot`, очистите BuildKit-кэш и пересоберите образ:

```bash
docker compose down
docker builder prune --all --force
docker compose build --no-cache web
docker compose up -d web
```

Осторожно с глобальной очисткой:

```bash
docker system prune --all
```

Эта команда удаляет неиспользуемые образы, остановленные контейнеры и сети Docker во всей системе, а не только в этом проекте. Не используйте `--volumes`, если не уверены, что вам не нужны Docker volumes других проектов.

## ⚙️ Конфигурация системы

Все ключевые настройки вынесены в файл `src/config.py` и поддерживают переопределение через переменные окружения:

```python
# Настройки отступа блюра от краев лица
FACE_PADDING_PERCENT_X = 0.35
FACE_PADDING_PERCENT_Y = 0.35

# Порог уверенности нейросети YuNet (0.3 - оптимально для мелких лиц)
YUNET_MIN_CONFIDENCE = 0.3

# Сканировать каждый N-ный кадр (увеличьте для скорости, уменьшите для плавности)
DETECT_EVERY_N_FRAMES = 28

# Ограничение FPS обработки. 30 FPS снижает нагрузку на CPU для VFR/60 FPS видео.
MAX_PROCESSING_FPS = 30.0

# Параметры H.264 кодирования обработанных чанков
OUTPUT_VIDEO_PRESET = os.environ.get("OUTPUT_VIDEO_PRESET", "ultrafast")
OUTPUT_VIDEO_CRF = os.environ.get("OUTPUT_VIDEO_CRF", "26")

# Количество параллельных воркеров по умолчанию (ограничено CPU_COUNT - 1)
CPU_COUNT = os.cpu_count() or multiprocessing.cpu_count() or 1
MAX_ALLOWED_WORKERS = max(1, CPU_COUNT - 1)
MAX_WORKERS = max(1, min(MAX_ALLOWED_WORKERS, int(os.environ.get("VIDEO_MAX_WORKERS", CPU_COUNT - 3))))

# Смещение тональности голоса (в полутонах. Отрицательные значения делают голос ниже)
PITCH_SHIFT_SEMITONES = -2.0

# Локальная автотранскрибация и диаризация спикеров
MODELS_DIR = os.environ.get("MODELS_DIR", os.path.join(BASE_DIR, "models"))
TRANSCRIPTION_ENABLED_DEFAULT = os.environ.get("TRANSCRIPTION_ENABLED", "true").lower() not in ("0", "false", "no", "off")
DEFAULT_ASR_MODEL = os.environ.get("DEFAULT_ASR_MODEL", "turbo").lower()  # turbo | parakeet | small
DEFAULT_COMPUTE_DEVICE = os.environ.get("ASR_DEVICE", "cpu").lower()      # cpu | cuda
DIARIZATION_CENTROID_SIM_THRESHOLD = float(os.environ.get("DIARIZATION_SIM_THRESHOLD", "0.54"))
```

### Подбор количества воркеров

Начинайте с `4-6` воркеров на обычных 6-ядерных CPU и сравнивайте общее время обработки одного и того же видео. Важен не пик загрузки CPU, а строка `Total time` в логах. Если первые чанки идут значительно дольше последних, значит система перегружена и количество воркеров стоит уменьшить.

Приложение не позволит выбрать больше `(количество логических CPU - 1)`, чтобы оставить системе хотя бы один поток для ОС, Docker и браузера. В режиме `CPU` выбранное число потоков также передаётся движкам транскрибации после склейки видео; в режиме `GPU CUDA` транскрибация работает параллельно с видеообработкой на видеокарте, не отнимая потоки у воркеров размытия лиц.

## 📁 Структура проекта

```text
├── src/
│   ├── models/            # Встроенная ONNX модель детекции лиц (YuNet)
│   ├── audio_processor.py # Анонимизация и pitch-shifting звука
│   ├── cancellation.py    # Потокобезопасный токен отмены задач и остановки процессов
│   ├── config.py          # Конфигурация видео, воркеров и профилей ASR/диаризации
│   ├── ffmpeg_utils.py    # Работа с FFmpeg: метаданные, чанкинг, склейка, WAV 16 kHz
│   ├── io_manager.py      # Управление временными папками задач
│   ├── model_manager.py   # Локальный кэш, автозагрузка и валидация весов моделей
│   ├── orchestrator.py    # Оркестратор конвейера (видео + питч + CPU/GPU транскрибация)
│   ├── transcriber.py     # Диаризация спикеров, мультиязычный ASR и сборка .txt
│   └── video_processor.py # Ядро анонимизации лиц: YuNet, интерполяция, блюр
├── static/
│   ├── index.html         # Главная страница (Claymorphism UI)
│   ├── script.js          # Логика UI (кастомные селекты, CPU/GPU, загрузка, поллинг)
│   └── style.css          # Стили тем, дроп-даунов, тумблеров и анимаций
├── tests/                 # Модульные и интеграционные автотесты (pytest)
├── app.py                 # FastAPI сервер и HTTP API
├── main.py                # CLI-интерфейс запуска обработки и транскрибации
├── docker-compose.yml     # Стандартный запуск контейнера (CPU)
├── docker-compose.gpu.yml # Опциональный оверлей для проброса NVIDIA GPU (CUDA)
├── Dockerfile             # Сборка образа (с опциональным ARG PRELOAD_MODELS)
└── requirements.txt       # Python зависимости
```
